# Scirocco 3.3.0 - 2026-11-05

Notice: Scirocco may trigger false-positive antivirus alerts.

Notice: builds from this fork are not code-signed, so Windows SmartScreen reports an unknown
publisher on first run. Choose "More info" then "Run anyway" to continue.

This beta adds HDR10+ dynamic metadata for HEVC and AV1 streams, resolution changes during an
active stream, gentler video pacing for remote clients, and NVENC improvements (working
intra-refresh option, bitrate changes without a keyframe). It also makes the Remote Monitor honor
the client's HDR request, moves PyroWave's D3D12 conversion to a high-priority queue by default,
hardens several privileged Windows paths, fixes mouse and scroll input batching and long pasted
text, keeps telemetry and unlock permissions when saving a client in the web UI, updates the
bundled scry so the Final Fantasy VII Rebirth telemetry can tell which area the player is in, and
brings in the latest upstream Vibepollo changes (Steam Controller support, Dolby audio, installer
fixes and more).

## Changes
- Added the `hdr_dynamic_metadata` option (off by default, Windows only). When on and the stream
  is PQ 10-bit HEVC or AV1, the host measures each frame's luminance on the GPU and adds HDR10+
  (SMPTE ST 2094-40) metadata to the video: a prefix SEI for HEVC, a metadata OBU for AV1. H.264,
  SDR, software-encoded and PyroWave streams are unchanged, and clients that ignore HDR10+ keep
  the static HDR10 metadata. There is no protocol change.
- Added the `allow_client_resolution_change` option: a client can change the stream resolution
  from its game menu without reconnecting. The host switches the display mode and restarts the
  encoder at the new size. It needs the automatic resolution option and a stream started with
  "Optimize game settings"; clients that do not support it are not affected.
- Video packets are now paced gently for remote clients (VPN or internet, packets of 1024 bytes
  or less): each frame is sent at the higher of 4x the stream bitrate and 20 Mbps instead of in a
  sub-millisecond burst. LAN clients, PyroWave sessions and sessions with an explicit pacing
  ceiling are unchanged.
- The `nvenc_intra_refresh` option now takes effect. It was shown in the web UI but never read;
  intra-refresh is now enabled by the option or by the client's request, for H.264, HEVC and AV1.
- NVENC now changes the bitrate in place, without a keyframe, when the driver supports it, so
  adaptive bitrate increases no longer cost a keyframe burst. Other drivers keep the previous
  behavior.
- The Remote Monitor virtual display now honors the client's HDR request. The host applies HDR on
  that exact display and reads the state back; HDR is used for capture only when the readback
  confirms it, otherwise the monitor falls back to SDR. A display shared with a normal game
  capture is only verified, not changed.
- PyroWave on Windows now converts frames with the D3D12 backend by default, on a high-priority
  compute queue (it falls back to normal priority, and the fallback is logged). Sessions using
  RTX HDR, or with `VIBESHINE_PYROWAVE_CONVERSION=d3d11` set, keep using D3D11.
- Hardened privileged Windows paths: the display helper is now authenticated over a private pipe
  that only SYSTEM can open, the elevated MSI payload is kept out of ProgramData, the install
  root must be a folder beneath Program Files, RTSS hooks must be signed and located in Program
  Files, web UI logins are rate-limited, the request buffer is capped and credentials are kept out
  of logs.
- Fixed relative mouse movement and scrolling: the overflow check in input batching was inverted,
  so normal motion was never coalesced (one blocking input call per report) and an overflowing
  sum could flip the direction of a very fast movement or scroll.
- Pasted text is now typed one character at a time with a short pause every 16 characters,
  instead of all key presses followed by all releases, which dropped text after about 60
  characters.
- Fixed the web UI devices view dropping the telemetry and unlock permissions: loading a client
  masked them out of the draft with a stale permission mask, so every save revoked them. Saving a
  client now keeps both.
- scry is pinned to 0.1.0-alpha.8. It can filter a list it reads, which the Final Fantasy VII
  Rebirth profile (contract 1.3) uses to report the location volumes the player stands in, so a
  Zefiro view can show the area's name and the region map.

### From upstream Vibepollo
- Steam Controller (2026) support over the VHF virtual gamepad.
- Keyboard and mouse input now defaults to an automatic mode that prefers the VHF driver, which
  is pinned to the released package.
- Optional Dolby Digital (AC-3) and Dolby Digital Plus (E-AC-3) audio output, and an option to
  send continuous audio on a single output clock.
- Host adaptive packet pacing, opt-in.
- Clients can be enabled or disabled from the API and web UI, and system apps can be removed and
  restored.
- Display fixes: Remote Monitor retries and color verification, the negotiated launch viewport is
  preserved, the stale remote display layout is removed when a client is unpaired, the primary
  display preference is retained for extended streams, and the matching virtual display driver
  release is pinned.
- Windows installer: the install folder is validated after elevation and replacements are
  validated before the working host is removed. Checks are scoped to packaged files and their
  parent folders, uncertain checks warn instead of blocking, and rejections report the affected
  path and the failed Windows operation (upstream 2.0.3 to 2.0.5).
- Fixed a display helper access problem that could prevent virtual displays from activating when
  starting a stream.
- AMF keeps the driver's slice count when it refuses the client's; cached game tiles stay
  launchable on remote clients; pairing records are validated before reauthorization; the
  Playnite fullscreen setting is preserved when saving an app in the legacy web UI; paused
  applications are observed after clients disconnect.
- Linux: Hyprland KMS can launch Steam games, and packaging and icon fixes.

### Build and tests
- The Windows CI job saves its compiler cache from master builds only. This affects build times,
  not the host.
- Fixed the HDR10+ code failing to build with GCC 14 and the AMF test harness, and the RTSS
  signature check failing to compile with MinGW.
- Restored the Windows installer unlock cleanup actions and scry output capture that the upstream
  merge had dropped.

## Known issues
- Releases from this fork are unsigned.
