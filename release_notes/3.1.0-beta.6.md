# Scirocco 3.1.0 - 2026-10-20

Notice: Scirocco may trigger false-positive antivirus alerts.

Notice: builds from this fork are not code-signed, so Windows SmartScreen reports an unknown
publisher on first run. Choose "More info" then "Run anyway" to continue.

A client can now unlock a locked PC when it starts a stream, and this release merges a round of
upstream fixes for capture pacing, display recovery, pairing, stream teardown, game focus and the
Playnite connector.

## Changes
- Unlock a locked Windows session when a stream starts. A client with the new "Unlock this PC"
  permission that starts or resumes a stream while the PC is locked makes the host sign in with
  a stored account password; the host locks the session again when the last stream ends, but
  only if it did the unlocking. Configure it in Settings -> Network & security.
  - Windows' "Hello-only sign-in" setting no longer blocks unlocking: third-party credential
    providers still load, so the host always tries the unlock. The settings page shows an
    informational note only when an attempt really failed to find a provider while Hello-only
    is on.
- Fixed the device permissions page dropping "Receive game telemetry" and "Unlock when
  streaming": the permission was lost when a client was loaded or saved, so telemetry never
  stuck and saving any other setting revoked it. The same applied to the pairing page.
- Smoother Windows Graphics Capture: frames are admitted by the compositor's own cadence, the
  concurrent startup cadence is preserved, and capture keeps running when the GPU priority boost
  fails. Cursor visibility now reaches the capture helper. From upstream (Nonary's Vibepollo).
- Video pacing honours a configured ceiling, including rates below one packet per millisecond,
  and refuses sessions that cannot fit under it instead of silently raising the cap. Shared
  capture follows the fastest live client when several are connected. From upstream.
- Display recovery is more reliable: saved HDR is restored after layout changes, and the
  physical primary monitor, inactive displays and awakened monitors are preserved across boot
  recovery and reconnects. From upstream.
- Pairing no longer imports stale recovery state for a rejected primary, and named clients are
  kept when legacy state is imported. From upstream.
- Graceful disconnects now finish on the control thread, and stream timer and priority
  ownership is retained on Windows. From upstream.
- Steam libraries are discovered from service sessions, and the tray's startup waits are
  cancelled when Windows shuts down. From upstream.
- The Playnite connector (0.5.2) can authenticate the host running as SYSTEM without
  elevation, which fixes the connector failing to connect for normal-user Playnite. Update the
  connector when Playnite offers it. From upstream.
- RTSS selects Reflex using the stream's GPU, NVIDIA cleanup finishes before shutdown, and
  the historical stats page fits mobile screens. From upstream.
- When the selected virtual display is still waking up or inactive, launching no longer swaps
  it for the headless fallback, and the fallback stays in place when the display cannot be
  activated under the current policy. From upstream.
- The virtual controller driver is updated to a build that fixes a startup lifecycle error
  while controllers are being created. From upstream.
- The installer keeps a pending Windows reboot after a display driver replacement and stops
  further driver repair until it happens. Capture restarts now log their cause, to help track
  down periodic capture outages. From upstream.
- Virtual display preparation follows the right precedence: a client's own setting wins over
  the application's, and an explicit virtual selection at a higher level can lift an inherited
  verify-only mode while a virtual display is being prepared. When a client explicitly turns
  the virtual display off and the stream falls back to the physical monitor, the stream still
  succeeds and the client is told about it with a warning. From upstream.
- Game focus no longer gives up early on slow launches: the host waits for the game window to
  appear (Steam, Lutris and both Playnite launch paths) before the focus timeout starts
  counting. From upstream.
- The installer repairs a missing or failed virtual display device from a valid retained driver
  package instead of skipping setup, leaving healthy or disabled devices alone. From upstream.
- Linux: the Web UI explains that the tray setting is overridden by the machine service, the
  portal capture probe builds without DRM support, and upgrades recover after an unrelated FUSE
  program blocked the old-host scan. From upstream.
- Paired clients keep their identity on live connections: evicting a client from the endpoint
  cache can no longer make the host forget a connected client or lose the identity of its queued
  requests, and disabling or unpairing a client revokes its access straight away. From upstream.
- Stream teardown is steadier: stopped packet queues stay alive until every worker has finished,
  bitrate changes no longer stall the host's listener while a stream is stopping, and the
  application list refreshes after teardown instead of disturbing a stream being prepared.
  From upstream.
- Audio defaults from before the virtual display was set up are captured and kept until the
  stream's capture has ended, so display changes that remove monitor audio endpoints no longer
  lose them. From upstream.
- Pairing recovery: when duplicate pairing records stop the host from starting, an
  administrator can now prepare a recovery candidate by choosing explicitly which record to
  keep, instead of the host guessing. It is not yet verified on Windows. From upstream.
- Linux: native virtual display buffers use row pitches compatible with AMD GPUs. From upstream.

## Known issues
- When the game loses focus, telemetry stops and the client panel goes blank for a moment
  until the game is back in the foreground.
- SuccessStory usually refreshes a game's achievements only when the game closes, so unlocks
  can show up on clients after the session rather than during it.
- IGDB metadata has not yet been exercised against a live account.
- Releases from this fork are unsigned.
