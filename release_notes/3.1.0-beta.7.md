# Scirocco 3.1.0 - 2026-10-20

Notice: Scirocco may trigger false-positive antivirus alerts.

Notice: builds from this fork are not code-signed, so Windows SmartScreen reports an unknown
publisher on first run. Choose "More info" then "Run anyway" to continue.

This release fixes unlock-on-stream on passwordless / Windows Hello machines, where a locked PC
never unlocked, and renames the feature's internals to the fork's own name.

## Changes
- Fixed unlock-on-stream never working on PCs whose lock screen comes up in the sign-in
  (CPUS_LOGON) scenario instead of the workstation-unlock one -- common with passwordless /
  Windows Hello setups. The lock-screen credential provider only handled the unlock scenario, so
  it never started its pipe there and every attempt came back "unavailable" (with a misleading
  Windows-Hello note). It now handles the sign-in screen too, mirroring the original
  implementation it was ported from.
- Renamed the unlock feature's internals from "Vibepollo" to "Scirocco": the provider DLL
  (`SciroccoUnlock.dll`), its "Scirocco Unlock" friendly name, the named pipe and the stored
  credential keys. Upgrade note: if you had "Unlock when streaming" enabled, re-enable it once
  after updating (Settings -> Network & security) so the credentials are re-stored under the new
  names. The old provider DLL and stored secrets from before this update are left in place;
  remove them by hand if you want a tidy machine.

## Known issues
- When the game loses focus, telemetry stops and the client panel goes blank for a moment
  until the game is back in the foreground.
- SuccessStory usually refreshes a game's achievements only when the game closes, so unlocks
  can show up on clients after the session rather than during it.
- IGDB metadata has not yet been exercised against a live account.
- Releases from this fork are unsigned.
