# Scirocco 3.2.0 - 2026-10-26

Notice: Scirocco may trigger false-positive antivirus alerts.

Notice: builds from this fork are not code-signed, so Windows SmartScreen reports an unknown
publisher on first run. Choose "More info" then "Run anyway" to continue.

This release lets Zefiro's in-game menu take screenshots, save replays and record gameplay using
the capture tool configured on the PC, makes the IGDB library pass much faster, and brings in the
latest upstream Vibepollo capture, DualSense audio, controller recovery and display fixes.

## Changes
- Added the `capture_provider` option (Input, Windows): the tool on this PC that handles capture
  requests from a client's in-game menu -- screenshot, save the last few seconds, start/stop a
  recording. The host now presses the tool's shortcut itself, so every client uses the same tool
  without per-client setup and no longer depends on its held modifiers or keyboard layout.
  Choices are `gamebar` (Xbox Game Bar, the default), `nvidia` (NVIDIA app / GeForce Experience
  default shortcuts: Alt+F1, Alt+F10, Alt+F9) and `off`, which hides the capture entries on
  clients. It can be overridden per application. Saving a replay with NVIDIA needs Instant Replay
  turned on in the NVIDIA app; Game Bar's "Record that" needs background recording turned on in
  Windows settings under Gaming > Captures. The shortcut presses are ordered with the client's own
  input and never release a key the client is holding. Moonlight, Artemis and other clients see no
  difference.
- IGDB metadata is now resolved for the whole library in bulk instead of game by game. Store ids
  are looked up 200 at a time, name searches are batched ten per request and records are fetched
  200 at a time, skipping fresh cache entries, so a library of a few hundred games no longer
  takes minutes to refresh. If IGDB refuses a request the pass stops, and the games still waiting
  are retried on the next pass.
- The portable package build no longer treats the NVIDIA driver's `nvcuda.dll` as a missing
  dependency, so portable builds with TrueHDR support are produced again.
- Repaired unit tests that had been failing on Arch builds since 3.1.0-beta.1 (the WGC
  capture-stop test and the Linux tray metadata test), and made the Windows CI test fixtures
  compile under MinGW. No runtime change.

### From upstream Vibepollo
- WGC capture is lighter: GPU encoders read the helper's frame directly and, when the host keeps
  up, frames are published with a single copy. A requested keyframe is no longer delayed behind a
  repeated frame, and recovery keyframes are retried after a reference invalidation fallback.
- DualSense speaker audio is now produced and routed as an independent PCM stream to the
  controller, with ownership tracked per client so it survives fragmented packets and USB audio
  completion.
- Virtual controllers recover better after their device is removed: owned controllers are
  recreated, the latest held state is replayed, and battery state is kept.
- Reconnecting remote input sessions replace the old session cleanly instead of racing its
  cleanup, and each UDP stream peer is isolated from the others.
- RTX HDR can now be enabled for PyroWave streams on Windows; on Linux, RTX HDR highlights above
  1000 nits are restored and synthesized HDR works from SDR captures on Hyprland.
- The virtual display driver is opened before the virtual screen catalog is checked, and an
  unobserved display driver is shown as informational in the Web UI instead of as an error.
- The display driver installer bounds its Driver Store and PnP inventory queries and keeps the
  failure diagnostics, so a hung query no longer stalls installation and unknown inventory no
  longer lets an install go ahead.
- Steam launch entries for non-Windows platforms are excluded on Windows.
- Support log export redacts faster, and repeated discovery and polling messages no longer flood
  the logs.
- The Maintenance page navigation matches the Logs page.
- Virtual display reuse is stricter: a stable target is only picked when its device ContainerID
  and identity match exactly, ambiguous or duplicate matches are rejected, and recovery and capture
  stay bound to the exact display the stream owns.
- A virtual display left inactive by a fullscreen transition is reactivated in place, keeping the
  other monitors' modes, instead of waiting for a full display rebuild.
- Desktop geometry changes during a WGC session now update input mapping without restarting the
  capture, and touch/pen input is held back until the mapping is usable.
- `creds` no longer saves the help token or incomplete input after printing its usage.
- Present-latency statistics reset when the foreground process changes, so samples from an
  unrelated game no longer skew pacing.
- Display snapshots missing monitor origins are rejected, and requested mode catalogs are pinned to
  the driver's newer protocol; clients that do not ask for it keep the full mode list.
- New opt-in options, off by default: IddCx frame-push capture (falls back to WGC when
  unavailable), per-call video batch sizing by demand, borrowed leases on existing monitor
  targets, and an experimental D3D12 conversion stage for PyroWave.
- More diagnostics for Linux display modes, ViGEm rumble, DMA-BUF imports and shutdown phases.

### Build and tests
- Arch CI runs about twice as fast and no longer evicts the compiler caches; the test fixtures
  were brought up to date with the merged upstream code. No runtime change.

## Known issues
- When the game loses focus, telemetry stops and the client panel goes blank for a moment
  until the game is back in the foreground.
- SuccessStory usually refreshes a game's achievements only when the game closes, so unlocks
  can show up on clients after the session rather than during it.
- IGDB metadata has not yet been exercised against a live account.
- Releases from this fork are unsigned.
