# Scirocco 3.4.0 - 2026-11-25

Notice: Scirocco may trigger false-positive antivirus alerts.

Notice: builds from this fork are not code-signed, so Windows SmartScreen reports an unknown
publisher on first run. Choose "More info" then "Run anyway" to continue.

This beta adds generated covers for apps without a picture, a better HDR to SDR conversion and a
pairing fix, on top of the installer fix and the audio, gamepad and networking fixes compared to
3.3.0.

## Changes
- Apps that show the placeholder (no image path, `box.png`, or a picture the host cannot use) now
  get a cover drawn by the Windows host from the app's name: 600x900 for posters and 1920x1080 for
  heroes. Six styles are available (tonal, monogram, icon, editorial, glass, geometric), chosen
  with the new `generated_cover_style` option (default tonal). The same name gives the same image
  on every machine. Posters from Playnite or picked by hand, and the Xbox entry, are untouched;
  Linux keeps the placeholder. Clients that cache by art version fetch the cover once when an app
  leaves the placeholder.
- When the desktop is captured in HDR and the stream is SDR, highlights are now tone mapped with
  ITU-R BT.2446-1 method B instead of being clipped at 80 nits, out-of-gamut colors are limited,
  and the result is encoded in the negotiated primaries (BT.709, SMPTE 170M, BT.2020). The picture
  no longer depends on the Windows SDR white slider.
- Pairing a client whose device name is the reserved placeholder "self" now works: the host stores
  the client (under a usable name) instead of reporting the pairing as done while leaving the
  paired list empty, which lost the pairing the next time the client was launched.
- Restored the Windows setup bootstrapper and MSI install actions to the earlier stable flow. The
  install-folder validation introduced in 3.3.0 (the install root must be a folder beneath
  Program Files, checks scoped to packaged files, replacement validation before the working host
  is removed) is removed, since it could block installs and upgrades. Other hardening in 3.3.0,
  such as the authenticated display helper pipe, is unchanged.
- The installer no longer deletes every `.txt` and `.log` file in the install folder during
  migration.
- Removed the install-root guard from the MSI, together with its build step and tests.
- Audio capture keeps contiguous WASAPI samples when timestamps jitter, instead of treating them
  as gaps.
- DualSense rumble stops when gamepad emulation is disabled.
- UPnP port mapping accepts the "disconnected" IGD status reported by MiniUPnPc 2.2.8 and newer.
- The RTSP message limit is raised from 2 KiB to 16 KiB, so large session announcements (automatic
  FEC and bitrate, extra capability lines) are no longer refused with "Exceeded maximum rtsp
  packet size". Length checks on encrypted messages no longer add the client's declared length to
  a pointer, and the log names the client, the length and the limit.
- Certificate handling supports the OpenSSL 4 APIs.
- Linux: KMS capture tries a GPU copy before falling back to CPU upload, the Avahi client is
  released when the poll loop stops, and the KWin bridge is verified before it is preloaded.

### From upstream Vibepollo
- The installer rollback above comes from upstream Vibepollo 2.0.6, which keeps the newer
  installer checks on its Canary builds for extended testing.
- The WASAPI audio, DualSense rumble, UPnP, OpenSSL 4 and Linux fixes above come from upstream
  Vibepollo 2.18.9.

## Known issues
- Releases from this fork are unsigned.
